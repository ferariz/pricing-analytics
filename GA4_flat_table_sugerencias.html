Si se reconstruye la tabla sin incluirlo, no queda en la flat y hay que volver a la fuente para recuperarlo.It's one of the sources we use to resolve plan duration, and it covers rows no other source reaches. As far as we can tell no dbt model generates it (verified: 0 hits across 40 branches), so it has to be extracted from the raw export in the flat-table query itself. If the table is rebuilt without it, it won't be in the flat table and you'd have to go back to the source to recover it.

-- Medido sobre nuestra build de prueba, que ya trae el campo.
-- only_days_length = filas que ni item_variant ni el sufijo de item_id resuelven.
WITH r AS (
  SELECT event_name,
    REGEXP_EXTRACT(item_variant, r'^(\d+)-days?$') IS NOT NULL AS by_variant,
    days_length IS NOT NULL                                AS by_days_length,
    REGEXP_EXTRACT(item_id, r'-(\d+)-days?$')     IS NOT NULL AS by_itemid_suffix
  FROM `hly--data--digital--d3.ga4_flat_tables.ga4_esim_flat_table_test`
  WHERE event_name IN ('view_item', 'purchase')
)
SELECT
  event_name,
  COUNT(*) AS filas,
  COUNTIF(NOT by_variant AND NOT by_itemid_suffix AND by_days_length) AS only_days_length,
  ROUND(100 * SAFE_DIVIDE(
    COUNTIF(NOT by_variant AND NOT by_itemid_suffix AND by_days_length),
    COUNT(*)), 2) AS pct_only_days_length
FROM r GROUP BY event_name;

Filtrar user_pseudo_id NULL y deduplicar en la construcciónFilter user_pseudo_id NULL and dedup in the build

La tabla trae hoy 88,8M filas con user_pseudo_id NULL (eventos del widget de mensajería) y 1,17% de duplicados exactos. Un WHERE user_pseudo_id IS NOT NULL más un QUALIFY ROW_NUMBER() de desempate los dejan afuera sin cambiar el grano.The table currently carries 88.8M rows with NULL user_pseudo_id (messaging-widget events) and 1.17% exact duplicates. A WHERE user_pseudo_id IS NOT NULL plus a tie-breaking QUALIFY ROW_NUMBER() leave them out without changing the grain.

WHERE _TABLE_SUFFIX BETWEEN ... AND ...
  AND user_pseudo_id IS NOT NULL

QUALIFY ROW_NUMBER() OVER (
  PARTITION BY user_pseudo_id, event_timestamp, event_name, item.item_id
  ORDER BY (geo.country = '' OR geo.country IS NULL) ASC,
           (SELECT value.int_value FROM UNNEST(event_params)
            WHERE key = 'engagement_time_msec') DESC
) = 1

-- (a) Totales: NULLs y % de duplicados exactos sobre toda la historia
WITH k AS (
  SELECT user_pseudo_id, event_timestamp, event_name, item_id, COUNT(*) c
  FROM `hly--data--digital--d3.ga4_flat_tables.ga4_esim_flat_table`
  GROUP BY 1,2,3,4
)
SELECT
  (SELECT COUNT(*) FROM `hly--data--digital--d3.ga4_flat_tables.ga4_esim_flat_table`) total_filas,
  (SELECT COUNTIF(user_pseudo_id IS NULL)
   FROM `hly--data--digital--d3.ga4_flat_tables.ga4_esim_flat_table`) filas_user_null,
  SUM(c) - COUNT(*) filas_duplicadas,
  ROUND(100 * SAFE_DIVIDE(SUM(c) - COUNT(*), SUM(c)), 2) pct_dup
FROM k;

-- (b) Dónde se concentran los duplicados, en un día concreto.
--     Ajustá la fecha; la tabla está particionada por event_date, así que es barato.
WITH k AS (
  SELECT event_name, user_pseudo_id, event_timestamp, item_id, COUNT(*) c
  FROM `hly--data--digital--d3.ga4_flat_tables.ga4_esim_flat_table`
  WHERE event_date = DATE '2026-08-15'
  GROUP BY 1,2,3,4
)
SELECT
  event_name,
  SUM(c) - COUNT(*)               AS filas_duplicadas,
  COUNTIF(user_pseudo_id IS NULL) AS grupos_user_null
FROM k
GROUP BY event_name
ORDER BY filas_duplicadas DESC
LIMIT 20;
